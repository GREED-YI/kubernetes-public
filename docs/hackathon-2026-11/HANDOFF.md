## 4. 확정 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스 | **첫 전세 계약 가이드** (도메인: 공공 + 금융) |
| 팀이름 후보 | **도장 찍기 전에** (추천), 전세 과외, 첫 전세, 집지킴이 ("안심"이 들어간 이름은 안심전세 앱과 헷갈려서 비추천) |
| Problem | 안심전세 앱 같은 서비스가 있어도 사회초년생은 **등기부등본을 읽지 못하고, 위험 신호를 봐도 무엇을 해야 할지 모른다** |
| Target | 처음 전세 계약을 하는 20~30대 사회초년생 |
| Solution | 서류를 올리면 OCR로 위험 신호를 찾아 **쉬운 말로 설명**하고, 서류로 알 수 없는 위험은 **체크리스트와 외부 링크**로 확인하게 돕는다 |
| Expected Impact | 계약 전에 위험 신호를 발견하고, 놓치기 쉬운 절차(송금 직전 재확인, 전입신고, 보증보험)를 빠뜨리지 않는다 |
| 최종 목표 | **위험한 집은 피하고, 계약한다면 전세보증보험까지 들게 하는 것** |

### 핵심 기능 3개
| 기능 | 내용 |
|---|---|
| ① 서류 OCR 진단 | 등기부등본·건축물대장 업로드 → 값 추출 → **추출값 확인 화면** → 규칙 기반 위험 판단 |
| ② 결과 해석 | 위험 신호 / 이상 없음 / 미확인을 구분해 표시. 모든 항목에 쉬운 이름과 "왜 필요해요?" 설명. **"서류로 확인할 수 없는 위험"** 섹션을 항상 표시 |
| ③ 체크리스트 + 링크 | 시점·조건별 체크리스트를 3단계로 체크. 항목마다 외부 사이트 링크 |

### 서비스 흐름
```
① 주소, 매물 이름, 보증금, 건물 유형, 시세, 선순위 보증금(모름 가능), 대리인 여부 입력
      ↓
② 등기부등본 + 건축물대장 업로드 (원본은 OCR 후 즉시 삭제)
      ↓
③ OCR 추출 → [추출값 확인 화면] 사용자가 확인·수정
      ↓
④ 규칙 기반 판단 (키워드, 부채비율)
      ↓
⑤ 결과: 🔴 위험 신호 / 🟢 이상 없음 / ⚪ 미확인 / ℹ️ 서류로 확인할 수 없는 위험
      ↓
⑥ 조건별 체크리스트 (체크 + 링크)
      ↓
⑦ [💾 마이페이지에 저장하기] → 로그인 → 잔금일·입주일까지 이어서 체크
```

### 서비스 루프 (Q&A: "전세 계약은 2년에 한 번인데 왜 다시 쓰나요?")
집 구하는 2~4주 동안 매물 여러 개를 진단해 마이페이지에 모아 봄 → 계약 후 잔금일·입주일까지 체크리스트로 계속 사용 → 다음 이사 때 다시 사용

## 5. 서류·정보 분류

### 구분 기준
| 구분 | 기준 |
|---|---|
| 📄 OCR 자동 판단 | 업로드한 서류에 글자로 적혀 있고, 키워드·숫자로 규칙 판단이 가능한 것 |
| ⌨️ 입력 / API | 서류에 없거나 외부 데이터가 필요한 숫자 |
| ☑️ 체크리스트 | 사람이 직접 보고 행동해야 하거나, 개인정보 때문에 업로드받지 않는 것 |

### 최소화 결과
| 구분 | 항목 |
|---|---|
| 📄 **필수 업로드 2개** | 등기부등본 (집합건물, 인터넷등기소), 건축물대장 (정부24) |
| 🔵 선택 업로드 1개 | 계약서 초안 (시간이 남으면: 계약서의 주소·임대인·보증금을 등기부와 교차 비교) |
| ⌨️ 입력 | 매물 이름, 주소, 내 보증금, 매매 시세, 건물 유형, 선순위 보증금(금액 또는 **"모름"**), 대리인 여부 |
| ❌ 업로드받지 않음 | 신분증, 위임장, 인감증명서, 납세증명서, 전입세대확인서, 확정일자 부여현황, 신탁원부 (개인정보 또는 법적 해석 영역) |

- **MVP OCR 범위는 집합건물(아파트, 빌라, 오피스텔)만**. 단독·다가구는 건물·토지 등기부가 따로라 체크리스트 + 선순위 보증금 직접 입력으로 처리 (다가구 OCR은 Next Steps)
- 선순위 보증금 **"모름"(`NULL`)과 "0원"(`0`)은 구분**. 모름은 ⚪ 미확인으로 표시
- 신분증·위임장 사진은 받지 않고 **확인 결과만** 입력

### 팀원 체크리스트 원본 대조 (모두 반영됨)
등기부등본, 건축물대장, 계약서 초안, 집주인 신분증, 국세·지방세 납세증명서, 매매 실거래가, 전세보증금 반환보증, 단독·다가구 건물·토지 등기부, 전입세대확인서, 확정일자 부여현황, 기존 임대차 내역, 신탁원부, 신탁 동의 서류, 위임장 → 모두 OCR·입력·체크리스트 중 하나에 배치. 추가한 항목: 인감증명서, 중개대상물 확인·설명서, 중개사 등록 여부, 악성 임대인 조회, 입주 당일 전입신고·확정일자

## 6. OCR 판단 규칙

### 등기부등본
| 코드 | 위치 | 추출 값 | 판단 규칙 | 결과 |
|---|---|---|---|---|
| `REG_ISSUED_AT` | 상단 | 열람일시 | 오늘 기준 며칠 전인가 | 오래됐으면 ⚪ "최신본으로 다시 떼세요" |
| `REG_ADDRESS` | 표제부 | 주소, 동·호수 | 입력 주소와 일치하는가 | 다르면 🔴 즉시 중단 |
| `REG_OWNER` | 갑구 | 소유자 이름 | 표시만 함 | 체크리스트 "신분증 대조" 옆에 표시 |
| `REG_OWNER_CHANGED` | 갑구 | 소유권 이전 접수일 | 3개월 이내인가 | 🟡 최근 소유자 변경 |
| `REG_SEIZURE` | 갑구 | 압류, 가압류, 가처분, 가등기 | 키워드가 있는가 | 🔴 |
| `REG_AUCTION` | 갑구 | 경매개시결정 | 키워드가 있는가 | 🔴 (계약하지 않는 것이 안전) |
| `REG_TRUST` | 갑구 | 신탁 | 키워드가 있는가 | 🔴 + 체크리스트 `TRUST` 항목 추가 |
| `REG_MORTGAGE` | 을구 | 근저당권 채권최고액 | 합계 → 부채비율 계산 | 비율에 따라 🟢🟡🔴 |
| `REG_LEASE_RIGHT` | 을구 | 임차권등기 | 키워드가 있는가 | 🔴 |
| `REG_JEONSE_RIGHT` | 을구 | 전세권 | 키워드가 있는가 | 🟡 먼저 등록된 다른 세입자 |

### 건축물대장
| 코드 | 추출 값 | 판단 규칙 | 결과 |
|---|---|---|---|
| `BLD_USE` | 주용도 | 주거용인가, 근린생활시설인가 | 주거용이 아니면 🔴 |
| `BLD_VIOLATION` | 위반건축물 표시 | 있는가 | 🔴 |
| `BLD_ADDRESS` | 주소 | 등기부 주소와 일치하는가 | 다르면 🔴 |
| `BLD_AREA` | 전용면적 | 입력(또는 계약서) 면적과 비슷한가 | 차이가 크면 🟡 |

### 개발 주의점
1. **추출값 확인 화면 필수**: OCR이 숫자를 잘못 읽으면 판단이 뒤집힘. 사용자가 확인·수정
2. **말소된 권리는 제외**: 이미 갚은 근저당도 "말소" 표시와 함께 남아 있음
3. **PDF는 텍스트 추출을 먼저 시도**: 텍스트가 들어 있는 PDF라면 OCR보다 정확 (인터넷등기소 PDF가 그런지는 팀이 확인)
4. **OCR은 값만 뽑고, 판단은 규칙이 함**
5. **데모는 가상 샘플 서류**로: "위험 신호 적은 집"과 "위험한 집" 두 세트
6. **원본 파일은 OCR 후 즉시 삭제**, 추출값만 저장
7. OCR 도구 후보: 네이버 CLOVA OCR, Google Vision, AI 비전 모델 (미정)

| 악성 임대인 | ❌ | 외부 링크 (안심전세 앱) |
| 위조 서류 | ❌ | 안내 ("직접 떼세요") |

### 보강 4가지 (반영 확정)
1. 업로드 화면에 **"서류는 중개사에게 받지 말고 직접 떼세요"** 안내 + 열람일시 확인
2. 결과 화면에 **"서류로 확인할 수 없는 위험"** 섹션 항상 표시
3. 체크리스트에 **악성 임대인 조회** 추가
4. **전세보증보험 가입**을 마지막 안전장치로 강조

### 발표 화법
| ❌ | ✅ |
|---|---|
| "OCR로 전세사기를 막습니다" | "서류에 드러난 위험 신호는 자동으로 찾아주고, 서류로 알 수 없는 위험은 무엇을 더 확인해야 하는지 알려줍니다" |
| "이 집은 안전합니다" | "서류상 발견된 위험 신호는 없어요. 다만 아래 항목은 아직 확인이 필요해요" |

**Q. OCR 결과가 깨끗하면 안전한가요?**
→ "아닙니다. 서류는 특정 시점의 기록이라 잔금일 기습 대출이나 가짜 집주인처럼 서류 밖에서 일어나는 사기는 잡을 수 없습니다. 그래서 '서류로 확인할 수 없는 위험'을 항상 보여주고, 송금 직전 재확인과 보증보험 가입까지 안내합니다."

## 8. 용어 설명 ("왜 필요해요?")

### 3단 설명 형식 (OCR 결과, 입력칸, 체크리스트 모두 동일)
| 단계 | 내용 | 표시 |
|---|---|---|
| ① 쉬운 이름 | 일상어 + 괄호 안에 원래 용어. 예: "집에 잡힌 대출 (근저당권)" | 항상 |
| ② 왜 필요해요? | 확인하는 이유 한두 문장 | 항상 (또는 ⓘ) |
| ③ 자세히 | 위험하면? / 어디서 확인? | 펼쳤을 때 |

원래 용어를 남기는 이유: 중개사·은행과 이야기할 때는 공식 용어를 써야 하므로

### 작성 원칙
중학생도 이해할 수 있게 / 한 문장에 정보 하나 / 겁주지 않고 단정하지 않기 ("~일 수 있어요") / 다음 행동까지 알려주기 / 원래 용어를 괄호에 남기기

### 서류 소개
- **등기부등본**: 집의 "이력서". 누가 주인인지, 집을 담보로 빌린 돈이 얼마인지 적혀 있음. 표제부(집 기본 정보), 갑구(주인 기록), 을구(빚 같은 다른 권리)
- **건축물대장**: 건물의 "신분증". 어떤 용도로 지었는지, 불법으로 고친 곳이 없는지 적혀 있음

### 등기부등본 항목
| 원래 용어 | 쉬운 이름 | 왜 필요해요? | 위험하면? |
|---|---|---|---|
| 열람일시 | 서류를 뗀 날짜 | 등기부는 하루 만에도 바뀔 수 있어요. 오래된 서류로는 지금 상태를 알 수 없어요. | 계약 직전에 새로 떼서 다시 확인하세요. |
| 표제부 주소·동호수 | 서류 속 집 주소 | 계약하려는 집과 서류 속 집이 같은지 확인해요. | 다르면 다른 집의 서류예요. 계약을 멈추세요. |
| 갑구 소유자 | 진짜 집주인 이름 | 계약하러 나온 사람이 진짜 주인인지 확인하는 기준이에요. | 이름이 다르면 대리인 서류를 확인해야 해요. |
| 소유권 이전 접수일 | 집주인이 바뀐 날짜 | 집을 사자마자 바로 전세를 놓는 경우, 돈 없는 사람에게 명의만 넘기는 사기 수법일 수 있어요. | 최근 3개월 안이면 집주인의 상황을 더 꼼꼼히 확인하세요. |
| 압류 | 빚 때문에 묶인 집 | 집주인이 세금이나 빚을 갚지 못해 집을 마음대로 팔지 못하게 묶어 둔 상태예요. | 경매로 넘어가 보증금을 돌려받기 어려울 수 있어요. |
| 가압류 | 임시로 묶인 집 | 빚을 받으려는 사람이 재판 전에 임시로 집을 묶어 둔 상태예요. | 경매로 이어질 수 있어요. |
| 가처분 | 처분 금지된 집 | 집을 두고 소유권 다툼 같은 분쟁이 있다는 뜻이에요. | 소송 결과에 따라 집주인이 바뀔 수 있어요. |
| 경매개시결정 | 경매가 시작된 집 | 이미 경매 절차가 시작됐다는 뜻이에요. | 계약하지 않는 것이 안전해요. |
| 가등기 | 주인 자리 예약 | 다른 사람이 나중에 이 집 주인이 될 권리를 미리 예약해 둔 거예요. | 그 사람이 주인이 되면 내 권리를 주장하기 어려울 수 있어요. |
| 신탁 | 신탁회사에 맡긴 집 | 서류상 진짜 주인은 신탁회사예요. 원래 집주인은 마음대로 세를 놓을 수 없어요. | 신탁회사 동의 없이 계약하면 보호받지 못할 수 있어요. |
| 근저당권 채권최고액 | 집에 잡힌 대출 | 집이 경매로 넘어가면 은행이 이 금액만큼 내 보증금보다 먼저 가져가요. 보통 실제 대출보다 20~30% 높게 적혀 있어요. | 대출과 보증금을 합친 금액이 집값에 가까울수록 위험해요. |
| 임차권등기 | 보증금을 못 받고 나간 기록 | 이전 세입자가 보증금을 돌려받지 못하고 나가면서 남긴 기록이에요. | 같은 일이 반복될 수 있어요. 이런 집에 새로 들어가면 소액 보증금 우선 지급 같은 일부 보호도 받지 못해요. |
| 전세권 | 먼저 등록된 다른 세입자 | 다른 세입자가 이미 공식적으로 권리를 등록해 둔 거예요. | 그 세입자가 나보다 먼저 보증금을 받아요. |
| 말소 | 이미 해결된 기록 | 줄이 그어지거나 "말소"라고 적힌 항목은 이미 정리된 기록이에요. | 판단에서 제외해요. |

### 건축물대장 항목
| 원래 용어 | 쉬운 이름 | 왜 필요해요? | 위험하면? |
|---|---|---|---|
| 주용도 | 건물을 지은 목적 | 사람이 사는 집(주거용)으로 지은 건물인지 확인해요. | 근린생활시설(상가용)이면 전세보증보험 가입과 전세대출이 거절될 수 있어요. |
| 위반건축물 | 불법으로 고친 건물 | 허가 없이 늘리거나 고친 건물에 붙는 표시예요. | 전세보증보험이나 대출이 거절될 수 있어요. |
| 주소 | 서류 속 건물 주소 | 등기부의 주소와 같은 건물인지 확인해요. | 다르면 서류가 잘못됐어요. |
| 전용면적 | 내가 실제로 쓰는 넓이 | 광고나 계약서의 넓이와 맞는지 확인해요. | 차이가 크면 방을 불법으로 쪼갰거나 다른 호수일 수 있어요. |

### 입력 항목
| 원래 용어 | 쉬운 이름 | 왜 필요해요? |
|---|---|---|
| 보증금 | 내가 맡기는 돈 | 이 돈을 나중에 돌려받을 수 있는지가 진단의 핵심이에요. |
| 매매 시세 | 지금 이 집의 가격 | 집값이 대출과 보증금을 합친 금액보다 충분히 커야 보증금을 돌려받을 수 있어요. |
| 건물 유형 | 어떤 집인가요? | 다가구주택은 세입자가 여럿이라 확인할 서류가 더 많아요. |
| 선순위 보증금 | 나보다 먼저 들어온 세입자들의 보증금 | 경매가 되면 먼저 들어온 세입자가 먼저 돈을 받아요. 모르면 "모름"을 고르세요. 0원과 모름은 달라요. |

### 결과 화면 용어
| 원래 용어 | 쉬운 이름 | 설명 |
|---|---|---|
| 부채비율 | 집값 대비 빚과 보증금 비율 | (대출 + 먼저 들어온 세입자 보증금 + 내 보증금) ÷ 집값. 100%를 넘으면 집을 팔아도 모두에게 돌려줄 돈이 모자라요. |
| 깡통전세 | 빈 깡통 같은 전세 | 빚과 보증금이 집값만큼 많아서 보증금을 돌려받기 어려운 집이에요. |

### 체크리스트 항목 설명
| 원래 용어 | 쉬운 이름 | 왜 필요해요? |
|---|---|---|
| 신분증 대조 | 진짜 집주인 맞나요? | 집주인인 척하는 사기를 막아요. 신분증 이름이 등기부 소유자 이름과 같은지 보세요. |
| 국세·지방세 납세증명서 | 집주인의 밀린 세금 확인 | 밀린 세금은 경매 때 내 보증금보다 먼저 가져갈 수 있어요. 집주인이 계약할 때 보여줘야 하는 서류예요. |
| 계약서 초안 | 계약서 미리 읽기 | 주소, 금액, 날짜가 틀리면 나중에 다툼이 생겨요. 나를 지켜주는 특약도 이때 넣어요. |
| 전세보증보험 | 보증금 지킴이 보험 | 집주인이 보증금을 못 돌려줘도 보증기관이 대신 돌려줘요. 가입이 안 되는 집이라면 그 자체로 경고 신호예요. |
| 중개대상물 확인·설명서 | 중개사의 설명 확인서 | 중개사가 집의 상태와 권리를 설명하고 책임지는 서류예요. 문제가 생기면 근거가 돼요. |
| 중개사 등록 여부 | 진짜 공인중개사인가요? | 등록된 중개사라야 사고가 났을 때 배상을 받을 수 있어요. |
| 악성 임대인 조회 | 문제 있는 집주인인가요? | 다른 집에서 보증금을 안 돌려준 이력은 이 집 서류에 나오지 않아요. |
| 송금 직전 등기부 재확인 | 돈 보내기 전 마지막 확인 | 계약일과 잔금일 사이에 집주인이 몰래 대출을 받을 수 있어요. |
| 계좌 명의 확인 | 집주인 본인 계좌인가요? | 다른 사람 계좌로 보내면 사기를 당했을 때 돌려받기 어려워요. |
| 전입신고 + 확정일자 | 내 권리 등록하기 | 전입신고를 하면 집주인이 바뀌어도 계속 살 권리가, 확정일자를 받으면 경매 때 순서대로 보증금을 받을 권리가 생겨요. 다음 날 0시부터 생기니 입주 당일 바로 하세요. |
| 건물 + 토지 등기부 | 건물 서류와 땅 서류 | 단독·다가구는 서류가 따로 있어요. 땅에만 대출이 잡혀 있을 수 있어요. |
| 전입세대확인서 | 이 건물에 사는 세대 목록 | 다른 세입자가 몇 세대 사는지 알 수 있어요. |
| 확정일자 부여현황 | 다른 세입자들의 보증금과 순서 | 먼저 들어온 세입자들의 보증금을 알 수 있어요. 집주인이 계약할 때 보여줘야 하는 정보예요. |
| 기존 임대차 내역 | 지금 세입자들의 계약 목록 | 선순위 보증금 합계를 계산하는 근거예요. |
| 신탁원부 | 신탁 계약서 | 누가 세를 놓을 권한이 있는지 적혀 있어요. |
| 신탁사 동의서 | 신탁회사의 허락 | 신탁회사의 동의 없이 맺은 계약은 보호받지 못할 수 있어요. |
| 위임장 + 인감증명서 | 대신 계약해도 된다는 허락 | 대리인에게 진짜 권한이 있는지 확인해요. 가능하면 집주인과 직접 통화하세요. |

⚠️ 위 문구는 일반적인 법·제도를 쉽게 풀어 쓴 것. 발표 전 팀원 한 명이 **국토교통부·HUG 공식 자료와 대조** 필요. 결과 화면에 **"참고용이며 법적 판단이 아닙니다"** 유지

### AI 역할

- 내 결과 요약: AI(선택). 키가 없으면 템플릿 문장으로 Mock

### 체크 상태 3가지
| 상태 | 표시 | 의미 | 결과 화면 |

## 11. 위험 점수 규칙 (초안, 팀이 조정 가능)

```
부채비율 = (근저당 채권최고액 합계 + 선순위 보증금 + 내 보증금) ÷ 매매 시세
```

| 조건 | 점수 |
|---|---|
| 부채비율 90% 이상 / 80~90% / 70~80% | +40 / +25 / +10 |
| 주소 불일치 (`REG_ADDRESS`, `BLD_ADDRESS`) | 즉시 🔴 + "계약 중단" |
| 경매개시결정 | +60 |
| 압류·가압류·가처분·가등기 (각) | +30 |
| 임차권등기 | +30 |
| 신탁 | +20 |
| 비주거 용도 / 위반건축물 (각) | +20 |
| 전세권 | +10 |
| 최근 3개월 소유자 변경 | +10 |
| 체크리스트 `RISK` (각) | +10 |
| 선순위 보증금 "모름" | 점수 없음, ⚪ 미확인으로 표시 (부채비율은 "최소값"으로 안내) |

| 점수 | 등급 | 표시 문구 |
|---|---|---|
| 0~29 | 🟢 | **"서류상 위험 신호가 적어요"** ("안전합니다"라고 쓰지 않음) |
| 30~59 | 🟡 | 주의가 필요해요 |
| 60 이상 | 🔴 | 위험 신호가 많아요 |

## 12. DB 설계 (최신, MySQL, 6개 테이블)

### 관계
```
users 1 ── N diagnoses 1 ── N ocr_extractions
                     │
                     1 ── N diagnosis_checks N ── 1 check_items 1 ── N check_item_links
```

### 처음 설계 대비 변경
- 제거: `properties`, `trade_records`(실거래가 캐시), `risk_factors`, `user_checklists`, `registry_questions`, `diagnosis_answers`, `checklist_items`
- 통합: OCR 항목·입력 항목·체크리스트 항목을 **`check_items` 하나**로 (설명 문구 포함). 진단별 상태는 **`diagnosis_checks` 하나**로

```sql
-- 1. 회원
CREATE TABLE users (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    email           VARCHAR(100) NOT NULL UNIQUE,
    password_hash   VARCHAR(255) NOT NULL,           -- BCrypt
    nickname        VARCHAR(30)  NOT NULL,
    created_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 2. 진단 (입력값 + 계산 결과)
CREATE TABLE diagnoses (
    id                  BIGINT AUTO_INCREMENT PRIMARY KEY,
    user_id             BIGINT       NULL,           -- 비로그인 NULL, 저장하면 회원 ID
    claim_key           CHAR(36)     NOT NULL UNIQUE,-- 로그인 후 계정 연결용 UUID
    title               VARCHAR(50),                 -- "신림동 빌라 A"
    address             VARCHAR(200) NOT NULL,
    building_type       VARCHAR(20)  NOT NULL,       -- APT, VILLA, OFFICETEL, MULTI_FAMILY
    is_agent            BOOLEAN      NOT NULL DEFAULT FALSE, -- 대리인 계약 여부
    deposit             INT          NOT NULL,       -- 만원
    market_price        INT,                         -- 만원
    senior_deposit      INT          NULL,           -- NULL = 모름, 0 = 0원
    mortgage_total      INT,                         -- OCR 근저당 합계 (말소 제외)
    debt_ratio          DECIMAL(5,2),
    risk_score          INT,
    risk_grade          VARCHAR(10),                 -- LOW, CAUTION, HIGH, STOP
    ai_summary          TEXT,                        -- AI 요약 (선택)
    created_at          DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
);

-- 3. OCR 추출값 (원본 파일은 저장하지 않음)
CREATE TABLE ocr_extractions (
    id                  BIGINT AUTO_INCREMENT PRIMARY KEY,
    diagnosis_id        BIGINT       NOT NULL,
    document            VARCHAR(20)  NOT NULL,       -- REGISTRY, BUILDING
    field_code          VARCHAR(40)  NOT NULL,       -- REG_MORTGAGE, BLD_USE ...
    extracted_value     VARCHAR(500),                -- OCR이 읽은 값
    corrected_value     VARCHAR(500),                -- 사용자가 고친 값 (없으면 NULL)
    is_cancelled        BOOLEAN      NOT NULL DEFAULT FALSE, -- 말소 여부
    FOREIGN KEY (diagnosis_id) REFERENCES diagnoses(id) ON DELETE CASCADE
);

-- 4. 항목 마스터 (OCR / 입력 / 체크리스트 + 설명 문구)
CREATE TABLE check_items (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    code            VARCHAR(40)  NOT NULL UNIQUE,    -- REG_TRUST, CK_MOVE_IN ...
    category        VARCHAR(10)  NOT NULL,           -- OCR, INPUT, CHECKLIST
    document        VARCHAR(20),                     -- REGISTRY, BUILDING, NULL
    section         VARCHAR(20),                     -- TITLE(표제부), GAP(갑구), EUL(을구)
    show_condition  VARCHAR(20)  NOT NULL DEFAULT 'ALL', -- ALL, MULTI_FAMILY, TRUST, AGENT, HIGH_RISK
    stage           VARCHAR(20),                     -- PREPARE, BEFORE_SIGN, BEFORE_TRANSFER, MOVE_IN_DAY, HELP
    official_term   VARCHAR(50)  NOT NULL,           -- 근저당권 채권최고액
    plain_name      VARCHAR(50)  NOT NULL,           -- 집에 잡힌 대출
    why_needed      VARCHAR(300) NOT NULL,
    if_risky        VARCHAR(300),
    where_to_check  VARCHAR(200),
    risk_score      INT          NOT NULL DEFAULT 0,
    sort_order      INT          NOT NULL
);

-- 5. 항목별 외부 링크 (1:N)
CREATE TABLE check_item_links (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    check_item_id   BIGINT       NOT NULL,
    label           VARCHAR(50)  NOT NULL,           -- "인터넷등기소에서 떼기"
    url             VARCHAR(500) NOT NULL,
    sort_order      INT          NOT NULL DEFAULT 0,
    FOREIGN KEY (check_item_id) REFERENCES check_items(id) ON DELETE CASCADE
);

-- 6. 진단별 항목 상태 (OCR 판단 결과 + 체크리스트 체크)
CREATE TABLE diagnosis_checks (
    id              BIGINT AUTO_INCREMENT PRIMARY KEY,
    diagnosis_id    BIGINT       NOT NULL,
    check_item_id   BIGINT       NOT NULL,
    status          VARCHAR(10)  NOT NULL DEFAULT 'TODO', -- TODO(⚪), OK(✅), RISK(⚠️)
    source          VARCHAR(10)  NOT NULL,           -- OCR, INPUT, USER
    memo            VARCHAR(300),
    updated_at      DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (diagnosis_id)  REFERENCES diagnoses(id) ON DELETE CASCADE,
    FOREIGN KEY (check_item_id) REFERENCES check_items(id),
    UNIQUE KEY uk_diag_item (diagnosis_id, check_item_id)
);
```

### 설계 포인트
- 금액은 **만원 단위 INT**로 통일 (실거래가 API 단위와 같음)
- 설명 문구와 링크를 DB에 두어 **기획 팀원도 코드 없이 수정** 가능, 화면 3종이 **같은 설명 컴포넌트** 재사용
- 비로그인 진단(`user_id IS NULL`)은 일정 시간 후 삭제 (자동 삭제 스케줄러는 Next Steps)

## 13. API 목록 (최신)

| Method | URL | 로그인 | 설명 |
|---|---|---|---|
| POST | `/api/auth/signup` | ❌ | 회원가입 |
| POST | `/api/auth/login` | ❌ | 로그인 |
| POST | `/api/diagnoses` | ❌ | 진단 생성 (입력값). 로그인 상태면 `user_id` 저장. 응답에 `claimKey` |
| POST | `/api/diagnoses/{claimKey}/documents` | ❌ | 서류 업로드 → OCR → 추출값 반환 (원본 즉시 삭제) |
| PUT | `/api/diagnoses/{claimKey}/extractions` | ❌ | 추출값 확인·수정 후 확정 → 규칙 판단 실행 |
| GET | `/api/diagnoses/{claimKey}/result` | ❌ | 결과 (위험 신호 / 이상 없음 / 미확인 / 서류로 확인할 수 없는 위험) |
| GET | `/api/diagnoses/{claimKey}/checklist` | ❌ | 조건에 맞는 체크리스트 (설명, 링크, 상태 포함) |
| PATCH | `/api/diagnoses/{claimKey}/checks/{checkItemId}` | ❌ | 체크 상태 변경 (비로그인은 저장 전까지) |
| POST | `/api/diagnoses/claim` | ✅ | 비로그인 진단을 내 계정에 연결. 본문 `{ "claimKey": "..." }` |
| GET | `/api/me/diagnoses` | ✅ | 마이페이지 목록 |
| GET | `/api/me/diagnoses/{id}` | ✅ | 내 진단 상세 + 체크리스트 |
| PATCH | `/api/me/diagnoses/{id}/checks/{checkItemId}` | ✅ | 체크 상태 변경 |
| DELETE | `/api/me/diagnoses/{id}` | ✅ | 기록 삭제 |

- 조건 필터(`show_condition`)는 **백엔드에서** 처리: 다가구 → `MULTI_FAMILY`, OCR 신탁 감지 → `TRUST`, 대리인 → `AGENT`, 결과 🔴 → `HIGH_RISK`
- `/api/me/...`는 **인가 체크 필수**
